# Wafer

Wafer is an application platform for Web Audio. It defines a plugin protocol that lets multiple Web Audio apps work together, along with a host framework that implements it.

## Motivation

Most Web Audio apps today are built as self-contained, standalone tools, which makes it hard to combine several of them to actually produce a piece of music.

Wafer provides a protocol and a host framework for connecting apps, with the goal of enabling a DAW that composes music out of many cooperating Web Audio apps.

An existing Web Audio app can usually be embedded into a host by adding only a small amount of glue code.

## Architecture

A plugin app loaded into a host is called a _unit_.

Each unit is implemented either as an iframe or as a Web Component, and a host app can run many of them together.

iframe units are designed to be hosted on the same origin. Because the origin is shared, a child iframe can reference and share the parent page's `AudioContext`, so audio can be routed between the host and multiple units. Note events and clock signals are also passed by direct function calls rather than asynchronous messaging.

Units are framework-agnostic: any structure is fine as long as it produces an HTML page or a Web Component that follows the specification.

The host library consists of a framework-independent core, React wrapper components, custom-element wrappers built on Web Components, and a Vite plugin that loads units.

React, Vite, and TypeScript are the primary target stack and give the smoothest development experience. For other frameworks — or plain JavaScript — the Web Components wrappers let you build a host without React or Vite.

## Installation

```
npm install wafer-host
```

The `wafer-host` package contains the host framework, unit type definitions, and the Vite unit loader plugin.

```
wafer-host/core            Core implementation, no React dependency
wafer-host/react           React wrapper components
wafer-host/custom-elements Web Components wrappers
wafer-host/unit-types      Types and helpers used when implementing a unit
wafer-host/vite-plugin     Unit loader plugin for developing a host with Vite
```

## Implementing a unit

```ts
import { queryUnitInterface } from "wafer-host/unit-types";
const unitInterface = queryUnitInterface("wafer-v01");
const audioContext = unitInterface?.audioContext ?? new AudioContext();
const destinationNode =
  unitInterface?.audioOutputNode ?? audioContext.destination;

let oscillatorNode;
const synthesizer = {
  noteOn(noteNumber) {
    oscillatorNode = audioContext.createOscillator();
    oscillatorNode.frequency = MidiToFrequency(noteNumber);
    oscillatorNode.connect(destinationNode);
    oscillatorNode.start();
  },
  noteOff() {
    oscillatorNode?.stop();
    oscillatorNode = undefined;
  },
};
unitInterface?.completeSetup({
  unitAspects: {
    unitType: "instrument",
    viewSize: [400, 300],
  },
  noteInput: {
    noteOn(noteNumber) {
      synthesizer.noteOn(noteNumber);
    },
    noteOff() {
      synthesizer.noteOff();
    },
  },
});
// The UI can be built and rendered with any framework you like.
```

This is an example of a synthesizer unit implemented as an iframe.

The parent page injects a `queryUnitInterface()` function into the iframe's `window`. The `unitInterface` object it returns is the entry point for all communication with the host.

When writing a unit in TypeScript, use the typed wrapper around `window.queryUnitInterface` that `@wafer-host/unit-types` provides.

When the unit runs standalone, `window.queryUnitInterface` does not exist and `unitInterface` is `undefined`. The code above is written so that running the unit on its own during development does not throw.

`unitInterface.audioContext` is the host's `AudioContext`. Units should generally create and process nodes with this context.

`unitInterface.audioOutputNode` is the output node the host created for this unit. Wherever a standalone synth app would connect to `audioContext.destination`, connect to this node instead.

`unitInterface.completeSetup` tells the host that initialization is finished. Handlers for note input, clock input, persistence, and so on are passed as its arguments.

## Implementing a host

### With React and Vite

The example below uses React, Vite, and TypeScript. A working project lives in [`example-apps/simple-session/`](example-apps/simple-session).

```tsx
import { createHostSystem } from "wafer-host/core";
import { HostAppProvider, UnitFrame } from "wafer-host/react";
import { createRoot } from "react-dom/client";

import catalog from "./unit-inventories.json"; // catalog generated by the loader plugin

const hostSystem = createHostSystem();

const App = () => {
  return (
    <HostAppProvider hostSystem={hostSystem}>
      <UnitFrame
        unitId="effect1"
        unitUrl={catalog.sunsetDelay.loaderPageUrl}
        destSpec="$output"
      />
      <UnitFrame
        unitId="synth1"
        unitUrl={catalog.webaudioTinySynthMini.loaderPageUrl}
        destSpec="effect1"
      />
      <UnitFrame
        unitId="sequencer1"
        unitUrl={catalog.tonerioSequencer.loaderPageUrl}
        destSpec="synth1"
      />
    </HostAppProvider>
  );
};

const root = createRoot(document.getElementById("app")!);
root.render(<App />);
```

The Vite unit loader plugin fetches the units ahead of time and writes a JSON catalog containing their local URLs, which the host code then reads.

Create a `hostSystem` instance with `createHostSystem()` from the core module, then use `<HostAppProvider />` and `<UnitFrame />` from the React wrapper.

`<UnitFrame />` is the element that wraps a single unit. Pass it a local URL from the catalog to instantiate the unit; the unit's `iframe` is rendered in place.

`unitId` assigns a unique ID to the unit instance, and `destSpec` names the unit ID to connect to. `$output` is a special value bound to the audio output that reaches your speakers or headphones.

There is also `<UnitFrameScaled />`, which automatically scales the unit to fit its parent container. Use whichever fits your layout.

```ts
export const unitSourceUrls = [
  "https://cdn.jsdelivr.net/gh/yahiro07/wafer-units@r16/graphite-drum-machine/",
  "https://cdn.jsdelivr.net/gh/yahiro07/wafer-units@r16/tonerio-sequencer/",
  ...
];
```

This is how you declare the units to import; the list is passed to the unit loader plugin.

Here the units are pre-built folders in a GitHub repository, pulled in through jsDelivr. URLs must start with `https://cdn.jsdelivr.net/gh`, and any GitHub repository can be referenced.

To use your own units, build them into a runnable bundle and push the built pages to GitHub.

When the dev server starts, the Vite plugin downloads and caches these units locally and maps requests to the cached content. On a production build they are emitted as local assets.

### With vanilla JS

This example uses the Web Components wrappers from plain JavaScript. Loading the host library requires ESM. A working sample lives in [`example-apps/simple-session-vanilla/`](example-apps/simple-session-vanilla).

```js
import {
  createHostSystem,
  createSequencerTickDriver,
} from "https://esm.sh/wafer-host/core";
import { registerCustomElements } from "https://esm.sh/wafer-host/custom-elements";

const hostSystem = createHostSystem();
registerCustomElements(hostSystem);
```

The host library is loaded on page load via esm.sh. Create a `HostSystem` instance with `createHostSystem()`, then call `registerCustomElements()` to define the Web Components tags.

```html
<div>
  <unit-frame
    unit-id="synth1"
    dest-spec="effect1"
    url="units/webaudio-tinysynth-mini/index.html"
  ></unit-frame>
  <unit-frame
    unit-id="drum1"
    dest-spec="$output"
    url="units/graphite-drum-machine/index.js"
  ></unit-frame>
  <unit-frame
    unit-id="sequencer1"
    dest-spec="synth1"
    url="units/tonerio-sequencer/index.html"
  ></unit-frame>
</div>
```

Registration defines both `<unit-frame>` and `<unit-frame-scaled>`. The snippet above uses `<unit-frame>`.

`unit-id` sets the unique unit ID, `dest-spec` names the unit ID to connect to, and `url` points to the unit to load.

The example project includes a `fetch-units.sh` script that downloads unit implementations from GitHub into a `units` folder. Run it before starting development.

## Building the framework

```sh
cd lib/wafer-host
pnpm install
pnpm run build
```

There are no special prerequisites or setup steps — `pnpm run build` is all you need.
